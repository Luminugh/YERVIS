# F3.06 — Etapa 4: engine Sherpa offline integrado

**Fecha:** 2026-10-12. **Estado:** pipeline contractual implementado y probado con PCM local determinista y un fixture humano público en Pixel 8 API 35 x86_64. **Aceptación de voz humana en vivo:** pendiente; no se cierra F3.06.

## Implementación

`SherpaOfflineSpeechToTextEngine` implementa `SpeechToTextEngine` y reutiliza `AudioRecordPcmSource`, `LifecyclePcmCapture`, `SileroPcmSegmenter` y `SherpaOfflineRecognizerAdapter`. La composición de producción adjunta el owner del ciclo de vida, prepara VAD y RNNT antes de abrir `AudioRecord`, captura mono PCM16 a 16 kHz en bloques de 20 ms, segmenta con Silero y decodifica cada segmento con FastConformer RNNT local. No usa `SpeechRecognizer`, servicios de red ni fallback cloud; los tags de idioma admitidos se restringen a español.

El resultado parcial se publica después de reconocer segmentos cerrados por VAD; `finish()` detiene la captura y solicita vaciar el segmento pendiente. El job de sesión continúa VAD/ASR y solo publica `Result` tras decodificar; `finish()` retorna sin esperar el JNI para que el controlador pueda cancelar esa decodificación si el usuario abandona o descarta. El silencio termina como `NO_SPEECH`. Errores de permiso, captura, idioma, recursos del modelo y JNI se conservan como errores tipados. El engine rechaza una segunda sesión activa. Cancelación, revocación y salida del owner descartan el borrador de voz y esperan la liberación de captura, VAD y Sherpa; la salida de lifecycle no se interpreta como una parada solicitada. El PCM de los bloques, segmentos y copia entregada al decoder síncrono se pone a cero al terminar su uso. El texto resultante vive solo en el estado de sesión para que la capa llamante lo trate como borrador; no se conecta a Room ni se sobrescribe el borrador textual existente.

Un seam pequeño `LocalPcmInput` permite conducir el mismo pipeline con PCM reproducible sin micrófono. El test JVM integra el engine con `VoiceCaptureSessionController`; el test Android reemplaza solo el origen por el fixture PCM y carga los modelos reales Silero/Sherpa. La UI no se conecta en esta etapa: F3.07/F3.08 mantienen su alcance.

## Validación

- `assembleDebug`: correcto.
- `testDebugUnitTest`: **126/126**, 0 fallos, errores u omitidos; 9 pruebas nuevas del engine cubren éxito, silencio, excepción de reconocimiento, denegación/revocación, cancelación durante decodificación final, salida de lifecycle, idioma no admitido, modelo ausente, prevención de sesiones concurrentes y liberación de recursos. También se comprueba que la copia PCM del decoder se borra sin modificar el buffer del llamante.
- `assembleDebugAndroidTest`: correcto.
- En AVD Pixel 8 API 35 x86_64, el test instrumentado focalizado del engine pasó **1/1** con conectividad apagada (`Active default network: none`). PCM humano FLEURS es_419/CC-BY-4.0 (9,72 s, sin micrófono): transcripción obtenida: “fue tanta la cantidad de gente que se concentró, que no todos pudieron acceder al funeral en la plaza de San Pedro.” La prueba recorre controller → contrato → VAD real → RNNT/JNI real. No es una medición de voz en vivo ni de latencia pura.
- Diagnóstico instrumentado del micrófono: **1/1**. `RECORD_AUDIO` estaba concedido, AppOps indicó modo foreground/allow, Android `MIC` abrió e inició la grabación, el sistema no indicó mute, y la prueba no fue rechazada por cliente silenciado. Con la entrada de audio del host del AVD activada para la prueba, `AudioRecord` devolvió 320 muestras/20 ms, **29 no cero**; el contenido se puso a cero y solo se registró el conteo. No hubo una persona pronunciando una frase y no se ejecutó ASR de ese buffer; por tanto no acredita habla inteligible. Antes, una lectura de 320 ceros sigue siendo compatible con ausencia de señal acústica o ruta de host vacía; estos datos no identifican por sí solos la causa exacta.
- Instalación y runner fueron focalizados con `adb install -r` y `am instrument`, sin `pm clear` ni desinstalación. El inode/tamaño de `yezvi.db` permaneció `573937 / 12.288 bytes`, y el sentinel sintético conservó `573712 / 29 bytes`. Se verificó `airplane_mode_on=1`, Wi-Fi/datos apagados y red por defecto `none`; se restauraron `airplane_mode_on=0`, Wi-Fi/datos activos y red por defecto disponible. El AVD sigue instalado con datos previos.

## Privacidad, distribución y límites

El manifiesto fusionado solo declara `RECORD_AUDIO`; no contiene permiso `INTERNET`. No se añadieron permisos, dependencias, descargas, llamadas de red, logs de texto privado, archivos PCM ni escrituras de persistencia. El test usa exclusivamente el fixture FLEURS público preexistente con hash/licencia fijados; no leyó ni copió el WAV privado del usuario.

El APK debug actual mide **220.095.209 bytes** por los recursos de modelo ya empaquetados; no se produjo ni distribuyó un artefacto nuevo. Continúa pendiente resolver la entrega de avisos/fuente correspondiente de eSpeak NG y UCD-tools GPL-3.0-or-later incluidos en el AAR sherpa-onnx; no distribuir el APK hasta esa revisión. La limitación y atribuciones del código, modelos y corpus están en [F3.02](F3.02-evaluacion-sherpa.md), [Etapa 2](F3.06-etapa2-vocabulario.md) y [auditoría GPL](../INVESTIGACION/F3.06-stt-local/etapa2-gpl-auditoria.md).
