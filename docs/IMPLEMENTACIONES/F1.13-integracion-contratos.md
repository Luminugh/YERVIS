# F1.13 — Integración de contratos y preparación para persistencia

## Resultado

Se auditó la integración de los contratos de F1.01–F1.03 con navegación, captura, timeline y detalle (F1.06–F1.12). Se corrigieron incompatibilidades concretas sin cambiar el diseño de las pantallas ni añadir dependencias.

## Contratos y flujos integrados

- `CaptureInput` conserva literalmente `rawText`, junto con `sourceType`, instante UTC (`capturedAtEpochMillis`) y `timezoneId`. `CaptureScreen` crea una instantánea al abrir la revisión; no recorta texto ni recalcula la fecha durante recomposiciones.
- `MemoryEntry` y `CaptureStatus` se reutilizan sin duplicar modelos. Las entradas demo mantienen IDs deterministas y `IDLE`; siguen siendo datos de demostración, sin indicar que fueron guardados.
- `MemoryUiCallbacks` es la frontera de intención de UI: captura, navegación a destinos y selección por `MemoryEntry.id`. El host `YezviApp` conecta los callbacks con `NavHost` y proporciona la fuente demo; las pantallas de memoria/detalle no consultan directamente `DemoMemoryRepository`.
- El detalle busca por ID en la lista demo recibida por el host y conserva sus estados de carga, encontrado, no encontrado y error. La ruta codifica el ID como segmento URI para IDs con caracteres reservados.
- Captura continúa en revisión y descarte: no existe una acción explícita de guardar, así que `onCaptureRequested` queda como hook de host y no se dispara. Esto evita fingir persistencia antes de F2.
- `TodayScreen` y su `DemoTodayItem` quedan intactos. `YezviBottomBar` conserva mínimo 48 dp por objetivo y no usa `fillMaxHeight()`; el resaltado no se expande a toda la pantalla.

## Riesgos y entrada a F2.01

- No hay escritura persistente ni acción UI de guardado. En F2.01 se debe evaluar compatibilidad real de Room/KSP con la configuración Kotlin/AGP existente, documentar versiones, alternativas y riesgos, y mantener el contrato de dominio independiente de Room.
- Para F2.02/F2.03, usar como datos canónicos ID, texto original, tipo de origen, instante UTC y zona horaria; definir cómo se representa el estado de captura antes de conectar guardado real. Mantener fixtures demo claramente separados de cualquier fuente persistida.
- No se registra ADR: esta integración aplica contratos y decisiones ya existentes, sin introducir una decisión arquitectónica nueva.
