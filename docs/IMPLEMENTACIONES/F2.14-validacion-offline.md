# F2.14 — Validación integral offline

## Resultado

La secuencia manual integral offline se completó con una nota sintética en el AVD Pixel 8 (API 35): captura, muerte forzada del proceso, reapertura, dos correcciones, verificación de original e historial, cancelación y confirmación del borrado, y reapertura sin el registro. El ANR observado en la ejecución anterior de Medium API 37 no se reprodujo; su causa exacta queda indeterminada porque no se conservó una traza de hilo que permita atribuirlo a YEZVI, al IME o al emulador. No se confirmó un defecto de la app y no se cambió código.

## Primera ejecución (Medium API 37) y protección de datos

- AVD `Medium_Phone_API_37.0`, `emulator-5554`, API 37. No había paquete YEZVI instalado antes de la sesión; se instaló el APK debug existente con `adb install -r`. No se usó `pm clear`, desinstalación ni reinicio del dispositivo.
- No había datos de YEZVI preexistentes que preservar en este AVD. Las pruebas instrumentadas usaron bases SQLite temporales con nombres únicos y entradas sintéticas; no tocaron la base principal.
- Antes de la prueba se deshabilitaron Wi‑Fi y datos móviles con `svc`; se confirmó `Active default network: none` y `ping 1.1.1.1` respondió `Network is unreachable` (modo avión permaneció apagado). Al terminar se reactivaron Wi‑Fi y datos móviles; el AVD volvió a tener red predeterminada validada.

## Flujo manual observado sin red

1. Se abrió YEZVI y se guardó desde Capturar el texto sintético `F214NoteOfflineSynthetic202610` (el campo limitó la entrada a 30 caracteres). La revisión mostró origen Texto, fecha 12 oct 2026, hora 10:29 y zona GMT; el mensaje de éxito indicó guardado local.
2. Memoria mostró la entrada persistida. Detalle mostró el texto original y los metadatos de captura (origen, fecha, hora, zona y guardado local).
3. `am force-stop` terminó el proceso (sin PID); al volver a iniciar la app, Memoria y Detalle recuperaron el mismo texto y metadatos. Esto verifica muerte forzada del proceso y reapertura, no un simple reinicio de Activity. No se reinició el AVD.
4. Al editar manualmente, la interacción de teclado/foco dejó de responder. `dumpsys activity lastanr` registró timeouts de `KeyEvent` (~10:32) y luego `FocusEvent(hasFocus=true)` (~10:34). La app se cerró desde el diálogo del sistema y se relanzó; no se guardó ninguna corrección en la nota. Por el ANR, no se completaron manualmente las dos correcciones ni el borrado de esta nota principal.

## Continuación F2.14 — diagnóstico en Pixel 8 (12 oct 2026)

- Se priorizó el AVD existente `Pixel_8`, API 35. YEZVI no estaba instalado en ese AVD; se instaló el APK debug existente sin borrar datos ni desinstalar. El primer arranque gráfico reportó `UpdateLayeredWindowIndirect failed` en el host y el AVD quedó offline; se inició después sin ventana con `swiftshader_indirect`, completó el arranque y se mantuvo sin `-wipe-data`. Esto es un problema de arranque/render del emulador en el host, distinto del ANR Android investigado.
- Se desactivaron Wi‑Fi y datos: `Active default network: none`, `ping 1.1.1.1` devolvió `Network is unreachable`, modo avión `0`. Se guardó desde Capturar `F214Pixel8Repro20261012`; Detalle mostró origen Texto, 12 oct 2026, 11:20, GMT y estado local. Tras `am force-stop` y relanzar, Memoria y Detalle recuperaron la misma nota y sus metadatos.

Se guardaron `F214Pixel8RevisionUno` y `F214Pixel8RevisionDos`. La UI mostró RevisionDos vigente, el original `F214Pixel8Repro20261012` intacto y las dos correcciones en orden.

La confirmación informó que el recuerdo y sus correcciones se eliminaron; Memoria no mostró la nota y siguió sin mostrarla después de cerrar forzadamente y reabrir la app. El registro de prueba del Pixel 8 quedó eliminado; no se modificaron otras notas.
