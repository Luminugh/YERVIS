# F2.06 — ViewModel, StateFlow y errores de guardado

## Alcance

Se creó `CaptureViewModel` en `presentation/capture`. Recibe `MemoryRepository` y `CaptureInput`, pero no depende de Room ni de componentes Compose. La pantalla de captura, callbacks, navegación y flujo de F2.07 permanecen intactos.

## Estados y guardado

`uiState: StateFlow<CaptureSaveState>` expone `Idle`, `Saving`, `Saved` y `Error`, cada uno relacionado con `CaptureStatus` de F1.01. `Saving` conserva la entrada original y el ID; `Error` mantiene esos mismos valores junto al error real para que el borrador siga disponible y `retry()` pueda repetir la operación. `Saved` solo se emite después de que `MemoryRepository.save` termina correctamente.

El ID se genera una vez en el límite de presentación con UUID. Los reintentos conservan ese ID; intentos repetidos mientras se guarda y la repetición del mismo input después del éxito no generan escrituras nuevas. El ViewModel entrega `CaptureInput` sin normalizar el texto ni recalcular origen, epoch UTC o zona IANA. No persiste `CaptureStatus` ni registra el contenido o la excepción en logs. Los fallos de almacenamiento se exponen como `Error`; `CancellationException` se relanza para preservar la cancelación del scope.

## Pruebas y dependencias

`CaptureViewModelTest` usa un `MemoryRepository` falso determinista y un dispatcher Main controlado. Verifica estados emitidos en éxito, bloqueo de llamadas repetidas, conservación del input ante fallo, reintento bajo el mismo ID y propagación de cancelación por `ViewModelStore.clear()` sin convertirla en un error de guardado.
