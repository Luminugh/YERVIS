# F2.05 — Repositorio persistente de memoria

## Alcance

Se añadió el contrato `MemoryRepository` en `domain/memory` y su adaptador Room en `data/repository`. El dominio y la presentación pueden depender del contrato sin conocer `MemoryEntryDao`; `DemoMemoryRepository` conserva su función de solo lectura y sigue separado. No se conectó ninguna pantalla ni callback y no se implementaron ViewModel o guardado de F2.07.

## Contrato y comportamiento

| Operación | Resultado |
|---|---|
| `save(CaptureInput, id)` (`suspend`) | Inserta usando el ID estable del llamador y devuelve `MemoryEntry` solo después de que Room confirme la inserción. |
| `findById(id)` (`suspend`) | Devuelve la entrada guardada o `null`. |
| `observeAll()` (`Flow`) | Emite registros de persistencia en `capturedAtEpochMillis DESC, id DESC`, conservando el orden definido por el DAO. |
| `update(entry)` (`suspend`) | Actualiza por ID y devuelve si existía una fila. |
| `deleteById(id)` (`suspend`) | Borra por ID y devuelve si eliminó una fila. |

`RoomMemoryRepository` reutiliza `CaptureInput.toMemoryEntryEntity` y los mapeos de fila. El nuevo `MemoryEntry.toMemoryEntryEntity` copia ID, texto, origen, epoch millis UTC y zona IANA sin conversión. `CaptureStatus` sigue siendo transitorio: no se guarda en SQLite y una fila leída se reconstruye como `SAVED`. Las excepciones de Room/SQLite no se capturan ni traducen; en particular, el ID duplicado conserva el comportamiento `ABORT` del DAO. No se añadió generador de IDs ni dependencia.
