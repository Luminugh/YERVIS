# F2.03 — Entity y DAO de memoria

## Alcance

Implementación de la representación Room y acceso tipado para el esquema v1 de F2.02. No se creó `@Database`, driver, repositorio, ViewModel, guardado UI ni migración; estos límites corresponden a F2.04 y posteriores. Las pantallas y contratos F1.01 permanecen sin cambios.

## Entity `memory_entries`

`MemoryEntryEntity` está en `data/local/memory` y conserva el orden de columnas del SQL aprobado en F2.02:

| Propiedad Kotlin | SQLite | Room |
|---|---|---|
| `id: String` | `TEXT NOT NULL` | `@PrimaryKey`, sin autogeneración |
| `rawText: String` | `TEXT NOT NULL` | Texto original literal |
| `capturedAtEpochMillis: Long` | `INTEGER NOT NULL` | Epoch millis UTC del contrato, sin conversión |
| `timezoneId: String` | `TEXT NOT NULL` | Zona IANA guardada como texto |
| `sourceType: CaptureSourceType` | `TEXT NOT NULL` | Enum serializado por nombre (`TEXT`/`VOICE`) |

La entidad declara el índice no único de `capturedAtEpochMillis` acordado en F2.02. Las propiedades no anulables producen columnas `NOT NULL`. No hay campos derivados ni estado de UI.

## DAO

`MemoryEntryDao` usa `androidx.room3` y funciones `suspend` para operaciones puntuales:

- `insert` con `OnConflictStrategy.ABORT`: no reemplaza silenciosamente una entrada si colisiona el ID estable.
- `findById`: búsqueda nullable por la clave primaria.
- `observeAll`: `Flow<List<MemoryEntryEntity>>`, ordenado por `capturedAtEpochMillis DESC, id DESC` para orden temporal y desempate estable.
- `update`: devuelve filas afectadas; Room empareja por ID.
- `deleteById`: devuelve filas eliminadas.

No se agregaron transacciones multioperación porque cada función modifica una sola fila. El DAO no elige cómo generar el ID.

## Mapeos y estados

Los mapeos pequeños en `MemoryEntryMappers.kt` conectan el contrato Kotlin puro sin introducir Room en el dominio: `CaptureInput.toMemoryEntryEntity(id)` recibe un ID estable del llamador y copia los cuatro valores sin alterar el texto ni la unidad del timestamp; `MemoryEntryEntity.toMemoryEntry()` asigna `CaptureStatus.SAVED`, pues representa una fila reconstruida desde persistencia. `IDLE`, `SAVING` y `FAILED` no se guardan. Una prueba JVM comprueba ID, texto con espacios/salto de línea, origen, epoch millis, zona y estado reconstruido.

## Dependencias

Se añadieron únicamente Room 3.0.3 runtime, su compilador y el plugin KSP 2.3.12/KSP2 en catálogo, raíz y módulo app. Kotlin/AGP/Gradle, SDK y pantallas no cambiaron. Context7 confirmó las firmas de DAO: `suspend` para operaciones puntuales y `Flow` para consultas observables; Room 3 usa la familia `androidx.room3`.

- `:app:assembleDebug` → `BUILD SUCCESSFUL`.
- `:app:testDebugUnitTest` → `BUILD SUCCESSFUL`; 15 pruebas, cero fallos.
