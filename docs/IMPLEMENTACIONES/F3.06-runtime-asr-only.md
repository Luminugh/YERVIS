# F3.06 — Reconstrucción de Sherpa sin TTS ni diarización

**Fecha:** 2026-10-14. **Alcance:** ejecución autorizada de la vía B del [plan de auditoría](F3.06-plan-auditoria-distribucion.md). No incluye F3.07 ni aceptación de micrófono humano.

> Para una revisión de procedencia, licencias, modificaciones, hashes y evidencias agrupadas fuera de los informes de fase, consulta el [expediente independiente de STT local F3.06](../AUDITORIA_LICENCIAS/F3.06-STT_LOCAL/README.md). Es un registro técnico, no una autorización legal de distribución.

## Decisión y alcance

Se conserva FastConformer español RNNT int8, Silero VAD, los contratos STT, AudioRecord y el controlador existentes. El AAR oficial completo se sustituye por un build propio de sherpa-onnx 1.13.8, revisión `11afbd009a7f8c08f4bcf2fc1b265d0df4670fbf`, sin TTS ni diarización. Vosk se conserva solo como prototipo debug: la comparación anterior no cumplió el criterio de velocidad/precisión.

No se atribuye al editor upstream este AAR modificado. La autorización del usuario comprende el NDK oficial r28c y la reconstrucción; no autoriza publicación. El NDK descargado de 748.118.221 B es una herramienta del PC, no se incorpora al APK. No se repitieron descargas de pesos.

Core y dependencias C++ estáticos, JNI compartido y **una sola** `libonnxruntime.so` por ABI. No se añade Maven ONNX Runtime ni el JNI del AAR completo. Se conservan `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`, API nativa 24 y `c++_static`.

Opciones: `BUILD_SHARED_LIBS=OFF`, `SHERPA_ONNX_ENABLE_JNI=ON`, `SHERPA_ONNX_ENABLE_TTS=OFF`, `SHERPA_ONNX_ENABLE_SPEAKER_DIARIZATION=OFF`, `SHERPA_ONNX_USE_PRE_INSTALLED_ONNXRUNTIME_IF_AVAILABLE=ON`; PortAudio, WebSocket, binarios, C API/ejemplos, Python, tests y aceleradores desactivados. Enlace JNI con `max-page-size=16384` y `common-page-size=16384`, mapa de enlace y comandos de compilación retenidos.

El root CMake antepone sus módulos a los de kaldifst: **OpenFst efectivo es 1.8.5-2026-07-09**, no la variante abril citada en un inventario histórico. También se resuelve Eigen 5.0.1. Los ocho archives se comprueban contra hashes CMake y se conservan localmente; el script de reconstrucción usa fuentes extraídas por ABI y FetchContent desconectado. Se conserva el parche Android de simple-sentencepiece que aplica upstream, sin inventar fidelidad al tokenizador Unigram original.

## Archivos y reproducción

- `scripts/Build-SherpaAsrOnly.ps1`: preflight local, hashes/checkout, configuración por ABI, compilación, strip sobre copias, AAR con timestamps fijos, avisos y recibo. No descarga, instala ni modifica recursos de la app.
- `scripts/Prepare-LocalSpeechResources.ps1`: prepara exclusivamente archivos ya presentes y verificados; Gradle falla si falta alguno o no coincide.
- `app/build.gradle.kts`: AAR propio en `implementation`; Vosk/JNA solo `debugImplementation`, verificación de recursos y aislamiento release. No cambian versiones de Kotlin/AGP/SDK/Room.
- Helpers Sherpa y pesos vuelven a `src/main`; Vosk/correspondientes tests/assets quedan en `src/debug`/`src/testDebug`. El diagnóstico de Ajustes sigue siendo exclusivamente debug y conserva Sherpa como selección inicial. No se conecta el guardado de voz ni se modifica Capturar/Room.
- `AsrOnlyRuntimeTest.kt`: inspección ELF del APK, carga/decodificación real, pipeline con PCM público/Silero/controlador y silencio; benchmark explícito sin micrófono.
- `scripts/Audit-SherpaAsrOnly.py` y [expediente](../INVESTIGACION/F3.06-asr-only/README.md): cotejo de artefactos, exclusiones, avisos y páginas nativas.

```powershell
# Requiere restaurar antes los archivos fijados del inventario; nunca descarga.
.\scripts\Build-SherpaAsrOnly.ps1 -Jobs 4
.\scripts\Prepare-LocalSpeechResources.ps1
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest :app:assembleRelease
# Instalación con -r; instrumentación directa, sin runners que desinstalen datos.
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -r -e class com.yezvi.assistant.data.speech.AsrOnlyRuntimeTest com.yezvi.assistant.test/androidx.test.runner.AndroidJUnitRunner
```

Los builds iniciales x86_64/ARM64 usan los mismos archives hash-verificados y flags; sus CMakeCache, comandos y mapas originales quedan preservados. `-SkipBuild` empaqueta esos resultados sin afirmar que se recompilaron mediante el wrapper. El recibo distingue esos metadatos de los builds nuevos del script. El ZIP determinista no demuestra builds C++ idénticos entre hosts/rutas absolutas.

## Licencias y distribución

La exclusión de eSpeak/Piper/UCD se verifica por dependencias configuradas, archivos compilados, mapa de enlace, exports y paquete. No basta buscar cadenas en un ELF. Desactivar diarización elimina hclust, pero no es lo que retira la cadena GPL de TTS. El build conserva otras funciones de audio/ASR de upstream: «sin TTS/diarización» no significa «solo objetos FastConformer».

La ruta conserva Apache-2.0/BSD/MIT, **Eigen MPL-2.0** y avisos/excepciones del runtime C++ de NDK. MPL admite combinar el código cubierto con archivos propios bajo otros términos, manteniendo avisos y acceso a su fuente cubierta; no es correcto describir este runtime como únicamente Apache/MIT. [FAQ oficial de Mozilla](https://www.mozilla.org/en-US/MPL/2.0/FAQ/), Q8–Q11; [Apache §4](https://www.apache.org/licenses/LICENSE-2.0).

El AAR incluye `META-INF/yezvi-stt/` con inventario, licencias y acceso al archive exacto Eigen; la app conserva los avisos en `assets/stt/`. NVIDIA/modelo/tokens/BPE siguen CC-BY-4.0 con atribución, extracción RNNT/exportación/cuanti­zación declaradas; Silero es MIT. Las muestras públicas FLEURS CC-BY-4.0 son solo fixtures de test. El WAV privado y sus referencias no son recursos distribuibles.

Los avisos agregados de ORT/NDK son superconjuntos; no prueban que todos sus componentes estén enlazados. ORT se coteja con el digest del paquete del mantenedor, pero no se reconstruyó su binario desde fuente. El expediente separa esta limitación de la evidencia de exclusión TTS del JNI propio.

Antes de publicación: conservar fuente Eigen accesible con su licencia, expediente/receta y avisos; elegir términos del código propio y canal; verificar el artefacto firmado final y todos los gates del plan. No se hace commit, staging de binarios ni push. El AAR/pesos se excluyen de Git normal; usar el inventario/receta o LFS/almacén de artefactos con revisión explícita. El encoder de 131.113.475 B supera el límite GitHub de 100 MiB.

## Resultados medidos y cierre

Ambos permanecen fuera de Git normal.
- `assembleDebug`, `testDebugUnitTest`, `assembleDebugAndroidTest`, `assembleRelease`: **BUILD SUCCESSFUL**. Los XML JVM contienen **148 pruebas, 0 fallos/errores/omitidas**. El primer build generó APK/tests y pasó las pruebas, pero falló al almacenar configuration cache: `layout` estaba capturado dentro de `doLast` del gate release. Se capturó el archivo del manifiesto fuera de la acción y la repetición justificada terminó en 28 s, con caché almacenada; tests ya ejecutados quedaron UP-TO-DATE. No se desactivó la caché para ocultarlo.
- APK debug **310.991.189 B** (incluye ambos motores/modelos de investigación); test APK privado **4.702.562 B**; release sin firmar **210.309.632 B**, SHA-256 `40e9b5b573c7007edc6fc9119326e31702bcc623f489ce4375c51f0854b654de`. El release excluye Vosk/JNA, fixtures y Activity desarrollador. Estos tamaños son universales de cuatro ABIs, no descarga medida de un AAB dividido por dispositivo.

### Confianza por palabra: capacidad actual y trabajo futuro

La integración **no devuelve una confianza ni una probabilidad de acierto por palabra**. En la API Kotlin fijada de sherpa-onnx 1.13.8, `OfflineRecognizerResult` expone `text`, `tokens` y `timestamps` (además de metadatos de otros modelos), sin un campo de confianza o log-probabilidades ([fuente oficial fijada](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/kotlin-api/OfflineRecognizer.kt)). `SherpaOfflineRecognizerAdapter` conserva el texto, las piezas BPE y sus tiempos; estos tiempos ubican tokens, no miden si son correctos.

**Actualización 2026-10-14:** se implementó una lectura experimental de scores por token y agrupado por palabra únicamente en debug; [informe del prototipo](F3.06-prototipo-confianza.md). El release conserva el AAR descrito aquí y no devuelve confianza por palabra. Sin una transcripción de referencia no se conoce el error real: incluso un score acústico alto no es por sí mismo una probabilidad calibrada de acierto. Las sugerencias automáticas requieren superar la evaluación independiente; el prototipo no se presenta como “porcentaje de precisión” ni forma parte de la aceptación de micrófono de F3.06.
