# F3.06 — Etapa 1: runtime y modelo STT local aislados

**Fecha:** 2026-10-12. **Alcance:** exclusivamente etapa 1 del plan aprobado.
**Resultado:** runtime integrado, modelo RNNT y VAD cargados mediante JNI/ONNX en Pixel 8 API 35 x86_64; decodificación de silencio controlado sin red. **F3.06 sigue pendiente de transcripción humana española, precisión y rendimiento reales.**

## Implementación y archivos

- `app/build.gradle.kts`: dependencia local exacta `libs/sherpa-onnx-static-link-onnxruntime-1.13.8.aar`; `verifyLocalSpeechResources` antes de `preBuild` verifica existencia, bytes y SHA-256 contra el manifiesto empaquetado. No hay resolución Maven de ORT adicional, cambios de versiones o descarga en tareas Gradle.
- `app/src/main/assets/stt/nemo-es-rnnt-int8/`: encoder, decoder y joiner int8 de FastConformer español RNNT, `tokens.txt` y `bpe.vocab`. `stt/silero_vad.onnx` contiene el VAD fijado por hash. No se empaqueta Whisper ni otro modelo.
- `stt/resources-manifest.json`, `ATTRIBUTIONS.md`, `licenses/` y `licenses-manifest.json`: procedencia, versiones, tamaños, hashes, licencias y advertencia de distribución. Ver inventarios originales [recursos](../INVESTIGACION/F3.06-stt-local/recursos-manifest.json) y [avisos suplementarios](../INVESTIGACION/F3.06-stt-local/avisos-terceros-manifest.json).
- `data/speech/LocalSpeechModelFiles.kt`: preparación de archivos, sin reconocedor de producción ni conexión a contratos de voz.
- `LocalSpeechModelFilesTest.kt`: 11 tests JVM nuevos. `LocalSpeechRuntimeTest.kt`: dos tests Android con JNI real.
- `.gitignore`, `.gitattributes` y `scripts/Prepare-LocalSpeechResources.ps1`: preparación reproducible de binarios locales con verificación explícita, sin staging automático. Los textos/vocabularios/avisos con SHA fijado preservan sus bytes sin conversión automática CRLF/LF en Git.

No se modificaron en esta etapa `CaptureScreen`, Room, permisos, schemas, `SpeechToTextEngine`, `VoiceCaptureSessionController` ni navegación. Esos archivos ya tenían cambios anteriores en el árbol de trabajo; no se deben atribuir a esta entrega.

## Preparación privada y publicación atómica

`LocalSpeechModelFiles(context).prepare()` usa `Dispatchers.IO` y devuelve seis rutas verificadas bajo:

```text
context.noBackupFilesDir/stt/d6d29ffd560c366da1b177b71e79d8733a9a9910dd1ace282d9bfae94e056210/
```

`noBackupFilesDir` excluye estos archivos de Auto Backup y transferencia de datos del sistema; no se amplía la política de backup de notas. La identidad del directorio corresponde al archive RNNT; cada preparación comprueba además individualmente VAD y vocabularios.

1. Mutex compartido por todas las instancias del proceso; no hay preparación simultánea de conjuntos incompletos.
2. Una caché solo se reutiliza si contiene exactamente seis archivos, tamaños y SHA correctos.
3. La copia escribe un directorio staging hermano, comprueba cancelación entre buffers, cierra streams y ejecuta `fd.sync()`.
4. Se valida el conjunto antes de publicarlo mediante rename en el mismo filesystem. Un reemplazo fallido intenta restituir la caché anterior.
5. La limpieza se limita a directorios planos propios: no atraviesa enlaces/directorios extraños y no accede a Room.

Límites explícitos: exclusión solo dentro del proceso actual; no soporta una futura arquitectura multiproceso. Una muerte del proceso puede dejar staging/reemplazo no publicado, sin convertirlo en modelo válido; la próxima preparación vuelve a validar. No se promete transacción durable entre dos renombres ante pérdida de energía, ni se borran automáticamente restos de otras versiones. Un consumidor JNI futuro deberá coordinar vida útil/reemplazos en la etapa correspondiente.

## JNI e inferencia aislada

El test abre `OfflineRecognizer(assetManager=null)` con las tres rutas RNNT, tokens, `modelType="nemo_transducer"`, CPU, dos threads, greedy search y debug desactivado. Características: 16 kHz, 80 bins, `dither=0f`.

Se alimentan **32.000 muestras Float32 iguales a cero** (dos segundos de silencio sintético mono), pasando directamente a ASR para que el VAD no evite la decodificación. Se ejecutan realmente `createStream`, `acceptWaveform`, `decode` y `getResult`. El resultado observado fue longitud 0/tokens 0; las aserciones verifican respuesta válida y timestamps finitos, sin convertir el silencio en una prueba de precisión española.

El segundo test carga Silero y procesa 32 bloques de 512 muestras cero: no produjo segmentos ni estado de habla. Esto valida el archivo/API nativo; todavía no implementa segmentación de micrófono.

Stream, recognizer y VAD se liberan en `finally`, en el mismo worker y sin liberar concurrentemente con JNI. El inventario contiene `es-spanish.wav` dentro del archive, pero su procedencia/licencia de uso no estaba certificada: no se extrajo, ejecutó ni incorporó. **No se validaron voz, español hablado, hotwords ni precisión.**

## APK, ABIs y límites de Git

APK debug final universal: **220.095.209 bytes (209,90 MiB)**; antes de esta etapa, APK local 12.664.543 B. La diferencia incluye pesos y cuatro ABIs, no una estimación de un APK de producción. Los seis archivos preparados ocupan **137.144.226 B** adicionales en almacenamiento privado. El tamaño comprimido del tar no representa el coste instalado ni la RAM.

Se conservan `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`. ARM64/x86_64 integran ORT dentro de `libsherpa-onnx-jni.so`; x86 también contiene el `libonnxruntime.so` previsto por el AAR. No se añadió otra copia/dependencia ONNX Runtime. No se introducen filtros ABI ni cambios de SDK. Un futuro paquete por ABI podrá reducir peso, previa decisión y validación.

El Pixel usa páginas **4096 B**; inspección ELF + zipalign no demuestran ejecución en un dispositivo de páginas 16 KB. No se probaron ARM64/S24 Ultra, API 24/37, release/R8, rendimiento conversacional, RAM, CPU o batería.

Encoder = **125,04 MiB** y archive = **102,28 MiB**, superiores al límite de 100 MiB de GitHub para Git normal. El AAR (36,90 MiB) cabe, pero tampoco se añade automáticamente al historial. La opción aplicada es **binarios ignorados + inventarios/provisionador versionables**; no se configuró Git LFS, no se hizo staging/commit/push.

En otro checkout:

1. Conservar/restaurar explícitamente el AAR, archive y VAD de las URLs del inventario en `.gradle/yezvi-stt-research/`; comprobar bytes/SHA antes de extracción. Estos tres recursos son menores de 200 MB individualmente; solicitar autorización antes de un recurso que supere ese umbral.
2. Extraer únicamente `encoder.int8.onnx`, `decoder.int8.onnx`, `joiner.int8.onnx`, `tokens.txt` del archive validado, a la carpeta fijada en el manifiesto. No extraer/ejecutar scripts ni audio de ejemplo.
3. `tokens.txt` y `bpe.vocab` son textos pequeños versionables. Si la caché no conserva BPE, restaurar allí el texto versionado (o derivarlo con el procedimiento documentado y comprobar el SHA), sin normalizar Unicode/line endings.
4. Ejecutar explícitamente `scripts/Prepare-LocalSpeechResources.ps1`. El script nunca consulta Internet y comprueba copia antes de rename. El build vuelve a comprobar hashes.
5. Mantener un respaldo externo de los binarios/licencias fijados: `.gradle` es descartable. Antes de distribuir, resolver las licencias indicadas abajo. Git LFS/release de recursos requerirían una decisión posterior; no subir un encoder ordinario a GitHub.

No se cambia el runtime por otro en esta etapa.
