# F1.12 — Pruebas UI/Compose, accesibilidad y previews

## Objetivo
Añadir cobertura de pruebas instrumentadas y unitarias para la interfaz construida en F1.06–F1.11, verificando navegación, flujo de captura, estados de detalle, semántica accesible y tolerancia a fuente grande.

## Qué se entregó
- **Navegación principal**: `YezviAppNavigationTest` verifica que las pestañas Hoy/Memoria/Capturar/Ajustes cambian de pantalla y que la línea temporal de Memoria muestra tarjetas con encabezados accesibles.
- **Flujo de captura**: `CaptureDraftFlowTest` escribe un borrador, abre la revisión, cierra el diálogo y confirma el descarte volviendo a Hoy.
- **Detalle y accesibilidad**: `EntryDetailAndAccessibilityTest` comprueba los estados Loaded/NotFound, headings semánticos, objetivos táctiles ≥48 dp y comportamiento con escala de fuente 1.5×.
- **Movimiento reducido**: `MotionSupportTest` confirma que las duraciones se anulan cuando `ANIMATOR_DURATION_SCALE = 0`.
- **Previews**: `EntryDetailScreenPreview` para diseño rápido.

## Ajustes de producción mínimos
- `YezviBottomBar`: los botones mantienen al menos 48 dp de altura táctil dentro de una fila de mínimo 80 dp; la superficie seleccionada no se expande verticalmente.
- `CaptureScreen`: `imePadding()` en el campo de texto y `testTag` para estabilidad en tests.
- `EntryDetailScreen`: `testTag` en el valor de origen para evitar ambigüedad con el distintivo.
- `MemoryScreen` / `TodayScreen` / `PlaceholderScreens`: `testTag` y `heading()` en títulos.

Resultado: `BUILD SUCCESSFUL` en las tres tareas. Emulador `Medium_Phone_API_37.0(AVD) - 17` ejecutó 8 tests instrumentados y 14 tests unitarios sin fallos.

## Riesgos / notas
- Los clics instrumentados sobre `ExtendedFloatingActionButton` y `Card` no fueron estables en este emulador; el flujo de captura se prueba desde la barra inferior y el detalle con `createComposeRule`. El comportamiento real de esos componentes fue validado manualmente.
- Algunos tests usan `waitUntil` con `onAllNodes(...).fetchSemanticsNodes()` en lugar de `waitForIdle()` para evitar bloqueos por animaciones del teclado virtual.
