# F3.01 — Investigación de SpeechRecognizer on-device

**Fecha:** 2026-10-12  
**Alcance:** investigación documental; no se implementó grabación/STT, no se pidió permiso, no se descargaron modelos ni se transmitió audio.

## Dictamen

`SpeechRecognizer` nativo es candidato viable para una ruta offline en dispositivos compatibles desde API 31, pero no alcanza para prometer transcripción española offline en todo el rango soportado por YEZVI (`minSdk 24`) ni en todos los Galaxy. La API depende de un `RecognitionService` presente, del modelo español concreto y de la versión/configuración del dispositivo. `EXTRA_PREFER_OFFLINE` no garantiza localidad. La promesa requiere comprobar el servicio y locale en runtime y transcribir con red deshabilitada en un Samsung físico objetivo.

F3.01 no selecciona motor. F3.02 debe comparar `SpeechRecognizer` con sherpa-onnx y medir en los equipos objetivo antes de que F3.03 defina una interfaz de motor.

## Capacidades por versión Android

| Android API | Capacidades relevantes | Límite para YEZVI |
|---|---|---|
| 24–30 | `SpeechRecognizer` existe desde API 8; `EXTRA_PREFER_OFFLINE` existe desde API 23. | No hay factory pública `createOnDeviceSpeechRecognizer`. La opción offline depende del servicio y puede ignorarse; no es un contrato de privacidad. En target 30+ también aplica visibilidad de paquetes (`<queries>` para `android.speech.RecognitionService`). |
| 31–32 | `isOnDeviceRecognitionAvailable()` y `createOnDeviceSpeechRecognizer()` aparecen en API 31. | El check solo confirma que hay un servicio on-device; no certifica que exista el modelo español o la variante regional requerida. Hay que manejar servicio ausente y errores `LANGUAGE_NOT_SUPPORTED` / `LANGUAGE_UNAVAILABLE`. |
| 33 | Se añaden `checkRecognitionSupport()` y `triggerModelDownload()`. | Permite consultar soporte para el `Intent`/locale y pedir soporte de modelo. La consulta debe hacerse sobre el servicio on-device; una descarga puede depender de red, quedar programada, requerir interacción o fallar. No sirve como prueba de funcionamiento sin red hasta tener el modelo disponible. |
| 34–37 | En API 34 se incorpora callback de progreso/resultado de descarga; también aparecen detección y cambio de idioma. API 35 añade opciones de duración/cantidad de cambios. | Estas opciones no aseguran español ni modo local: la implementación puede ignorar extras. En la documentación consultada no aparece una garantía general adicional para idiomas offline en API 36–37. `compileSdk/targetSdk 37` no significa que el dispositivo tenga el modelo. |

La compatibilidad del proyecto empieza en API 24, por lo que el contrato nativo on-device de Android no cubre todos los dispositivos admitidos. Si offline es requisito también en API 24–30, F3.02 debe evaluar un motor empaquetado como sherpa-onnx o proponer explícitamente un límite mínimo de versión; no recurrir a `EXTRA_PREFER_OFFLINE` como sustituto.

## Español y modelos

- Los idiomas se solicitan con etiquetas BCP 47 (`RecognizerIntent.EXTRA_LANGUAGE`). La disponibilidad es del servicio/modelo y puede distinguir región; probar primero `es-PE` por el uso previsto y registrar qué otras variantes devuelve el dispositivo, sin asumir que `es-ES`, `es-MX` o `es-419` sean equivalentes.
- En API 33+, el paso de preflight debe invocar `checkRecognitionSupport()` en el recognizer on-device para cada locale que se considere. Registrar por dispositivo si está utilizable o necesita preparación/descarga; no descargar en esta investigación. En API 31–32 no existe ese mismo query público por solicitud: hay que intentar la solicitud y representar correctamente errores de idioma/servicio.
- Samsung documenta descarga de paquetes de idioma para su función «Voice input» en Galaxy S23, pero eso describe una función de Samsung (por ejemplo, teclado/entrada de voz), no prueba que el `RecognitionService` que consume una app de terceros exponga el mismo modelo ni que acepte `createOnDeviceSpeechRecognizer`. La versión One UI, región, operador, modelo, servicio predeterminado y configuración importan.
- No se puede declarar “español offline” hasta reconocer audio español real con red desactivada y confirmar que la ruta usada fue on-device. Un modelo descargable tampoco es un modelo instalado; para uso offline hay que preparar el modelo antes del corte de red y verificar de nuevo sin conexión.

## Permisos, ciclo de vida y errores

- La app aún no declara `android.permission.RECORD_AUDIO`. Es necesario declararlo y pedirlo como permiso runtime contextual desde API 23; el flujo debe iniciar tras una acción clara del usuario, mostrar denegación/revocación y no grabar de fondo ni permanecer escuchando.
- El manifiesto actual tampoco incluye `<queries><intent><action android:name="android.speech.RecognitionService"/></intent></queries>`. La referencia de `SpeechRecognizer` exige esta visibilidad para apps target Android 11/API 30 o superior; YEZVI target API 37. Añadirla y el permiso pertenece a tareas posteriores, no se cambió en F3.01.
- Crear el recognizer, configurar listener, iniciar/parar/cancelar y destruirlo deben respetar el hilo principal según la API. Configurar `RecognitionListener` antes de enviar órdenes y llamar `destroy()` al finalizar. `stopListening()` finaliza la entrada capturada y se debe esperar `onResults()` o `onError()` antes de iniciar otra sesión; `cancel()` descarta la sesión. Ligar cancelación y destrucción al ciclo de vida/acción Atrás evita sesiones huérfanas.
- Representar errores por causa: permiso insuficiente, error de audio, sin voz/timeout, servicio ocupado/desconectado, idioma no soportado o soportado pero no disponible, y errores de red/servicio. No convertir fallo o cancelación en una transcripción vacía exitosa.
- La API genérica advierte que su implementación probablemente transmite audio a servidores; no está pensada para reconocimiento continuo. Evitar `createSpeechRecognizer()` genérico si el requisito es estrictamente local y no usar audio continuo/always-on.

## Pixel 8 AVD y Samsung físico

- **Pixel 8 API 35:** puede verificar presencia de la factory API 31, `isOnDeviceRecognitionAvailable()`, servicio de reconocimiento visible, permisos, consulta de soporte de locale de API 33 y estados de error/cancelación. La configuración de API permite esa investigación, pero no se hicieron llamadas ni se comprobaron modelos en esta tarea. La documentación Android indica que el emulador no graba audio de micrófono; por ello no valida captación física ni calidad acústica.
- **Galaxy físico:** es necesario para comprobar Samsung/One UI, el servicio realmente predeterminado, paquete de voz español instalado, interacción de descarga, operación con modo avión, captura del micrófono, reconocimiento de español peruano en ruido/uso normal, latencia, consumo térmico/batería y comportamiento al volver de background. El Galaxy S23 citado en el manual Samsung no sustituye una prueba del modelo objetivo de YEZVI.
- Esta investigación no ejecutó pruebas en Pixel 8 ni Samsung, no solicitó `RECORD_AUDIO`, no alteró permisos/manifest y no generó audio.

## Criterios de decisión para F3.02

**Preferir motor nativo** si el Galaxy objetivo tiene on-device service, enumera como disponible el locale español elegido, transcribe muestras acordadas con conectividad cortada después de preparar el modelo y supera objetivos de calidad/latencia; además, el producto acepta excluir API 24–30 de la promesa offline.

**Evaluar sherpa-onnx como ruta principal o respaldo** si el servicio on-device falta, el locale español no se ofrece/no puede prepararse, la operación sin red no se demuestra o se requiere offline uniforme en API 24+. Comparar ambos con el mismo conjunto de audio sintético/autorizado: calidad/WER en español peruano, exactitud de nombres, latencia inicial y por sesión, tamaño total del modelo, RAM, CPU/batería, cancelación/ciclo de vida, licencias y operación tras instalación/reinicio sin red. No agregar la dependencia ni descargar el modelo hasta que F3.02 lo justifique.
