# F3.02 — Evaluación de sherpa-onnx y modelos de español

**Fecha:** 2026-10-12  
**Alcance:** investigación documental con fuentes oficiales de sherpa-onnx, proyectos upstream de modelos y Android. No se descargaron modelos/binarios, no se hizo benchmark local, no se modificó Kotlin/Gradle/manifest y no se ejecutó Gradle.

## Dictamen provisional

Hay opciones sherpa-onnx locales en español para Android. La opción más ligera que encontré es **Moonshine base español cuantizado**, de 63 MB de pesos según el inventario publicado, pero el ejemplo Android lo clasifica como *simulated streaming*: segmenta/gestiona audio y ejecuta un reconocedor offline; no es un transducer online español. Como alternativa multilingüe offline por lotes, **Canary 180m Flash int8** ocupa alrededor de 198 MB de pesos. **Nemotron 3.5 ASR Streaming 0.6B int8** sí documenta streaming real y español regional, pero suma aproximadamente 650 MB de pesos. Ninguna de estas cifras predice RAM, batería ni rendimiento en un Galaxy.

No cierro la elección del motor. Es técnicamente posible preferir el servicio Android on-device donde esté disponible y usar sherpa-onnx local como alternativa; la app debe comprobar capacidad y conservar una ruta estrictamente local, sin degradar en silencio al reconocedor Android genérico o a la nube. Para API 24–30 sherpa sería necesario si el producto mantiene reconocimiento offline, porque la factory explícita Android on-device comienza en API 31.

El catálogo de transducers online revisado no mostró un modelo español monolingüe de esa familia. Para esta evaluación, no presento Moonshine como equivalente a streaming nativo: la documentación lo etiqueta expresamente como *simulated streaming*.

## Mediciones y estimaciones separadas

- **Mediciones de esta tarea:** ninguna. No se ejecutó sherpa en el Pixel 8 AVD ni en Samsung. El AVD API 35 documentado en el estado del proyecto sirve para pruebas de integración, no para certificar audio real.
- **Datos publicados:** los tamaños y el RTF 0.959/5.113 s para 5.329 s de audio de Moonshine español vienen de la documentación sherpa; el ejemplo usa CPU y dos hilos, pero no identifica hardware y no se extrapola a ARM64/Android. NVIDIA publica WER en conjuntos de evaluación para Canary (MLS/MCV-16.1) y Nemotron (FLEURS `es_419`), y pruebas de throughput/latencia sobre GPU H100 para Nemotron. Esos resultados usan upstream/modelos/configuraciones distintos y no son comparables directamente entre sí ni con el ejemplo sherpa. Los chunks de Nemotron son configuraciones, no medidas de latencia móvil.
- **Estimaciones/riesgos de distribución:** empacar Moonshine aumentaría al menos ~63 MB más las bibliotecas nativas del ABI; Canary ~198 MB más runtime; Nemotron ~650 MB más runtime. La APK/AAB instalada puede variar por compresión, splits ABI y método de entrega. El tamaño del archivo no permite inferir RAM pico. El modo totalmente offline desde el primer uso exige que modelo y runtime estén instalados antes de desconectar la red; descarga posterior solo da offline después de completarse.

## Compatibilidad y requisitos prácticos

- La app actual declara `minSdk 24`, `compileSdk 37` y `targetSdk 37`. La app demo de sherpa consultada declara `minSdk 21`, así que API 24 está dentro de su nivel de instalación de ejemplo. Esto no prueba ejecución sin fallos en cada API 24–37 ni compatibilidad de cada modelo, runtime NDK o combinación de ABI; probar mínimo API 24, API 35 y API 37 donde haya imágenes/dispositivos.
- sherpa-onnx integra código nativo ONNX Runtime/JNI. La guía oficial enumera `arm64-v8a`, `armeabi-v7a`, `x86_64` y `x86`; recomienda elegir solo ABIs que se distribuirán. Galaxy suele usar ARM64, pero compatibilidad de ABI no demuestra rendimiento, soporte de micrófono ni compatibilidad Samsung/One UI.
- No se publicó un mínimo verificable de núcleos, frecuencia o RAM para los candidatos. Medir inicialización en frío, memoria pico del proceso, RTF sostenido, latencia de primer parcial/final y consumo en hardware objetivo. La cuantización reduce almacenamiento/cómputo frente al modelo no cuantizado, pero no basta para predecir esos valores.
- Ambas rutas necesitan permiso contextual de micrófono para captura por la app. sherpa procesa el audio/modelo localmente si la integración no añade red; la ruta nativa solo debe llamarse local cuando se usa el servicio on-device explícito y la prueba offline confirma el resultado. `EXTRA_PREFER_OFFLINE` en la ruta Android genérica no es garantía. No permitir fallback remoto.

## Licencias y empaquetado

- El código sherpa-onnx declara Apache-2.0; su documentación advierte que hay modelos de distintos orígenes y que se revise la licencia del modelo elegido. La licencia del runtime no se extiende automáticamente a los pesos.
- El upstream oficial Moonshine clasifica **Spanish Base** entre sus modelos de voz no ingleses bajo Moonshine Community License, no MIT. Contempla uso no comercial y uso comercial condicionado; este último requiere registro, tiene un umbral de ingresos y obligaciones de distribuir el acuerdo y atribución, incluida la mención “Powered by Moonshine AI”. No incluirlo en YEZVI sin confirmar que el uso previsto y la forma de distribución cumplen esos términos.
- El modelo upstream oficial Canary declara CC-BY-4.0 y uso comercial permitido, con atribución y mención de cambios. Como la versión sherpa es convertida/quantizada, conservar los avisos y comprobar que la redistribución de ese artefacto derivado queda cubierta.
- El model card oficial de Nemotron declara OpenMDW-1.1 y uso comercial preparado; verificar los términos de esa licencia y del artefacto ONNX convertido antes de redistribuirlo. La licencia Apache-2.0 de sherpa-onnx cubre el código del runtime, no sustituye los términos de los pesos.
- Empaquetar pesos en assets da disponibilidad sin red desde instalación, a cambio de tamaño de descarga/almacenamiento. Un modelo descargado bajo demanda reduce el paquete inicial, pero requiere red y espacio antes del primer uso offline. No se recomienda descargar ni empaquetar hasta terminar evaluación de calidad, memoria, rendimiento y licencias.

## Recomendación provisional y criterios de prueba

Mantener **SpeechRecognizer on-device como primera ruta candidata en API 31+**, solo cuando `isOnDeviceRecognitionAvailable` y soporte del locale lo confirmen y una transcripción real funcione con red desactivada. Evaluar **Moonshine base-es** como alternativa local para API 24–30 o dispositivos sin servicio/modelo español, condicionada a aceptar su Community License. Es una hipótesis de producto, no una selección final; el RTF publicado de muestra cercano a 1x y sin hardware especificado hace imprescindible medirlo primero. Canary puede servir como comparación offline por lotes si Moonshine no logra calidad; Nemotron queda como comparación streaming de tamaño alto.

Plan para la siguiente validación de motor, sin ejecutar ahora:

1. Fijar versiones exactas, hashes y licencias. No comparar artefactos cambiantes.
2. Usar el mismo conjunto autorizado/sintético de voz española peruana en todas las rutas (frases cortas y largas, nombres propios, fechas, ruido leve); calcular WER/CER, exactitud de nombres/fechas y revisar puntuación manualmente.
3. En Galaxy físico registrar modelo, SoC, RAM, Android/One UI, servicio de reconocimiento y locales; probar `es-PE` y variantes que el servicio declare. Repetir desconectado, incluyendo instalación inicial, reinicio y nueva sesión.
4. Medir tiempo de inicialización fría, primer parcial, resultado final, RTF, memoria pico/PSS y energía en una sesión fija; reportar mediana y p95 en repeticiones. Mantener un objetivo de RTF < 1 como puerta provisional para dictado en vivo, ajustando latencia de parciales a la UX acordada.
5. Verificar en APK/AAB el tamaño final por ABI, instalación/API 24, Pixel 8 API 35 para integración (sin tomarlo como prueba de micrófono) y Galaxy objetivo para audio real/One UI. No cambiar la elección final hasta conocer esos resultados.
