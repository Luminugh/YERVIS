# F2.01 — Selección de Room/KSP

## Objetivo y alcance

Evaluar la configuración existente y recomendar una combinación para F2.02–F2.03. No se añadieron dependencias, plugins, entidades ni código de persistencia. La decisión quedó aceptada tras la prueba aislada de generación y compilación documentada en F2.02; la integración con el driver y la base definitiva se valida en F2.04.

## Versiones observadas

| Componente | Configuración actual | Observación |
|---|---|---|
| AGP | 9.4.1 (`libs.versions.toml`) | AGP 9.4 requiere Gradle 9.6, admite hasta API 37 y requiere JDK 17 como mínimo. |
| Gradle | Wrapper 9.6.0 | Confirmado también con `gradlew --version`. |
| Kotlin | 2.2.10 en el catálogo para `org.jetbrains.kotlin.plugin.compose`; AGP 9 usa Kotlin integrado | AGP 9.0 establece KGP 2.2.10 como dependencia runtime mínima. El `Kotlin 2.3.21` que muestra `gradlew --version` corresponde al Kotlin embebido de Gradle DSL, no al Kotlin del código de la app. |
| SDK Android | `compileSdk = 37`, `targetSdk = 37`, `minSdk = 24` | Build Tools no se fijan en el proyecto; AGP 9.4 usa 36.0.0 por defecto. |
| Java | JDK 25 para ejecutar Gradle (daemon criteria 25); source/target Java 11 | Gradle 9.6 admite ejecutar en Java 25; AGP requiere como mínimo JDK 17. |

## Decisión propuesta

**Room 3.0.3 + KSP 2.3.12 (KSP2)**, manteniendo Kotlin/AGP/Gradle sin cambios. Room 3.0.3 es la versión estable actual de Room. El proyecto es nuevo, exclusivamente Kotlin y no contiene código Room 2.x ni dependencias que exijan `androidx.room`; por ello, empezar con la API actual evita diseñar el esquema y DAOs sobre interfaces que después habría que migrar. KSP 2.3.12 es la versión estable actual publicada; su soporte mínimo declarado es AGP 8.12, inferior al AGP 9.4.1 del proyecto. KSP desde la línea 2.3 separa su versión de la del compilador Kotlin. La compatibilidad amplia está sustentada por documentación oficial, aunque no se publica una matriz que certifique exactamente la tupla AGP 9.4.1 + KGP 2.2.10 + KSP 2.3.12; el spike aislado de F2.02 validó generación y compilación con esa combinación.

Room 2.8.4 sería una alternativa conservadora si una biblioteca futura exige el paquete `androidx.room`/SupportSQLite o se decide priorizar compatibilidad con integraciones 2.x. La guía oficial usa Room 2.8 como etapa de preparación para Room 3, pero no hay código ni dependencia existente que justifique empezar en esa etapa intermedia. Room 3 cambia el paquete a `androidx.room3`, requiere KSP y generación Kotlin, usa APIs basadas en coroutines y reemplaza SupportSQLite por SQLiteDriver en su API principal; F2.02 debe adoptar estas formas desde el principio.

## Generación, esquemas, migraciones y pruebas

- El plugin KSP ejecuta el compilador de Room durante la compilación y genera las implementaciones de `RoomDatabase`/DAO; el código generado no se edita manualmente. Usar KSP2, la implementación actual de KSP; no habilitar KSP1 ni KAPT para Room 3.
- Alinear `room3-runtime`, `room3-compiler`, `room3-testing` y el plugin Gradle de Room en **3.0.3**. Al incorporar la base definitiva en F2.04, aplicar el Room Gradle Plugin `androidx.room3`, dirigir `schemaDirectory` a `app/schemas` y versionar los JSON exportados.
- No deshabilitar `exportSchema`: los archivos son historial reproducible y entrada de migraciones automáticas. Cambios ambiguos (por ejemplo renombrar/eliminar tabla o columna) necesitan `AutoMigrationSpec`; transformaciones de datos o cambios complejos requieren migración manual.
- Para F2.12, probar migraciones desde cada esquema soportado con `room3-testing`/`MigrationTestHelper` en instrumentación, además de pruebas de DAO/base en memoria. Verificar tanto schema como conservación de filas y valores; no usar destructive migration para resolver errores.
- Room 3 requiere operaciones asíncronas con `suspend` salvo tipos observables, y `Flow` si se necesita observación reactiva. Las dependencias explícitas de coroutines se evaluarán solo cuando F2.05 defina APIs `Flow`/`StateFlow`; no se agregan en F2.01.

## Riesgos y handoff

1. No hay matriz oficial para la tupla exacta KSP2–KGP del proyecto. El spike aislado exacto (AGP 9.4.1, Gradle 9.6.0, KGP integrado 2.2.10, KSP 2.3.12, Room 3.0.3, SDK 37/JDK 25/bytecode 11) generó el schema JSON y compiló la implementación Room; falta integración con el driver/base final en F2.04.
2. La nueva familia `androidx.room3` no es intercambiable con `androidx.room`; revisar dependencias futuras antes de integrar bibliotecas Android que usen Room 2.x.
3. Conservar como columnas canónicas del primer esquema `id`, `rawText`, `sourceType`, `capturedAtEpochMillis`, `timezoneId` y el estado solo si tiene semántica persistible; no almacenar fechas derivadas. Mantener fixtures demo fuera de la base real y mapear entre Room y los contratos Kotlin puros.

**Handoff original F2.01:** diseñar el esquema mínimo Room 3 en F2.02. Resultado y prueba de generación posteriores: [F2.02 — esquema de memoria](F2.02-esquema-memoria.md).
