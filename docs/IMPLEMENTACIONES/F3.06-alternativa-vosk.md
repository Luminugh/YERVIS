# F3.06 — Alternativa Vosk local: implementación y comparación real

**Fecha:** 2026-10-13. **Estado:** prototipo implementado y medido en Pixel 8 AVD API 35; **no sustituye al motor principal**. No supera todavía el requisito de igual velocidad/calidad. Distribución final pendiente de los gates documentados; F3.06 y micrófono humano siguen abiertos.

**Actualización 2026-10-14:** tras esta medición, el usuario autorizó la reconstrucción Sherpa sin TTS/diarización. Vosk/código/modelos/JNA quedan ahora en `src/debug` y `src/testDebug`; el release candidato vuelve a FastConformer con el AAR propio. La tabla de tamaños y la separación de variantes que siguen describen el snapshot Vosk medido, no el nuevo APK. Ver [rebuild ASR-only](F3.06-runtime-asr-only.md).

## Resultado

Se implementó una segunda ruta ASR completamente local mediante Vosk Android 0.3.75 y el modelo pequeño español `vosk-model-small-es-0.42`. Reutiliza `SpeechToTextEngine`, `VoiceCaptureSessionController`, permisos y la fuente PCM existentes. El apartado de diagnóstico debug permite elegir explícitamente Sherpa o Vosk; conserva Sherpa como elección inicial porque la nueva opción no superó la comparación de velocidad y calidad.

La separación de variantes deja el AAR, engines, helpers y assets Sherpa en debug para investigación privada. Vosk/JNA y su modelo se prepararon en main para generar un release candidato que no incorpore el AAR Sherpa con TTS/eSpeak. Esto es una transición técnica, **no una decisión de publicar o de convertir Vosk en motor principal**. La integración y la auditoría final podrán ajustarse al runtime ASR-only autorizado; véase [reconstrucción ASR-only](F3.06-runtime-asr-only.md), que registra su ejecución por separado.

### Audio, estados y recursos

- Vosk acepta PCM16 mono a 16.000 Hz; `length` cuenta **muestras**, no bytes. La fuente compartida entrega bloques de 320 muestras. No se inicia la captura al crear una factory ni al abrir la página.
- La ruta Vosk utiliza su decoder incremental y endpointing nativo; no añade Silero ni ONNX Runtime. La ruta Sherpa conserva su pipeline independiente AudioRecord → Silero → Sherpa.
- Un endpoint de Vosk no finaliza la sesión: se acumula su texto y los parciales siguen siendo revisables hasta `finish()`/EOF. El último fragmento se obtiene con `getFinalResult()`; no se reescribe el texto para ocultar errores.
- El resultado de éxito se publica después del flush y la limpieza. Cancelar descarta los resultados tardíos, detiene captura y espera al código nativo que ya esté ejecutándose antes de liberar sus objetos. No se promete interrupción instantánea de una llamada nativa bloqueada.
- PermissionDenied, OfflineModelMissing, EngineUnavailable, NO_SPEECH y fallos de captura/reconocimiento reutilizan los tipos existentes. Se conserva la propagación de cancelaciones y se evita transformar un fallo de cleanup en éxito.
- No guarda notas ni audio, no llama a Room y no contiene fallback cloud. Los logs de información del decoder se desactivan; el código no registra transcripciones.

No se diseñó UI final F3.08, ni se conectó el borrador F3.07. Tampoco se cambia el esquema de persistencia ni el guardado textual.

### Permisos de distribución identificados y límites

El código Vosk y el modelo concreto small-es-0.42 se identifican como Apache-2.0. JNA ofrece Apache-2.0 o LGPL-2.1-or-later: esta integración elige Apache-2.0 y conserva la licencia/aviso de esa elección. Se preservan además Apache de Kaldi/OpenFST, BSD de OpenBLAS/CLAPACK, permiso f2c, MIT de libffi y el header WTFPL de SimpleJSON sin inventar una versión.

Los avisos LLVM/libc++/compiler-rt son conservadores: la revisión exacta del toolchain que produjo el AAR precompilado no está demostrada. El script upstream fija algunas versiones pero clona Kaldi/OpenFST por branch; los snapshots del manifiesto prueban sus avisos, no que sean las fuentes exactas del binario entregado. Por ello no se declara SBOM integral/fuente reproducible cerrados ni aptitud jurídica absoluta de toda la app.

La GPL del AAR Sherpa completo no se traslada automáticamente a Vosk: son artefactos diferentes. La alternativa release necesita demostrar que no empaqueta Sherpa/eSpeak/UCD, además de cerrar sus propias licencias y dependencias. El debug que conserva esos componentes es solo para investigación privada mientras su auditoría siga pendiente; entregarlo a terceros también requiere revisar distribución.

Condiciones y plan: [auditoría y gate de distribución](F3.06-plan-auditoria-distribucion.md). No publicar APK/AAR de esta ejecución todavía.

## 3. Comparación A/B ejecutada offline

Fuente reproducible agregada, **sin texto privado**: [comparison-metrics.json](../INVESTIGACION/F3.06-vosk/comparison-metrics.json).

**Entorno:** Pixel 8 AVD API 35, x86_64, páginas 4096 B. Modelos locales, conectividad desactivada, sin micrófono. Se empleó la misma PCM para ambos motores; Vosk incremental en bloques de 320 y FastConformer RNNT `greedy_search` directo. No se aplicaron hotwords ni reemplazos posteriores. Se separaron preparación de archivos, carga e inferencia y se alternó el orden de los motores entre repeticiones del caso privado.

La diferencia de pipeline debe permanecer explícita: Vosk hace trabajo de decode mientras recibe bloques, y RNNT directo procesa el archivo completo. El tiempo total de inferencia medido incluye ese trabajo Vosk; el pequeño flush final no es una medida de latencia humana en vivo.

| Medida observada | Vosk small-es-0.42 | FastConformer RNNT int8 greedy |
| --- | ---: | ---: |
| Caso privado autorizado, duración | 66,01 s; 1.056.160 muestras | La misma PCM |
| Repeticiones caso privado | 3 | 3 |
| Inferencia mediana | **18.422,636 ms** | **8.250,042 ms** |
| Rango de inferencia | 16.386,552–19.076,870 ms | 7.301,220–13.610,700 ms |
| RTF mediano | 0,2791 | 0,1250 |
| Carga mediana en esas ejecuciones | 1.014,508 ms | 2.505,744 ms |
| WER contra referencia privada aproximada | 31,84–32,34 %; agregado de 3 ejecuciones **32,01 %** | **24,378 %**, igual en las 3 |
| Errores privados S/D/I por ejecución | 33/13/18; 33/13/19; 33/13/18 | 25/12/12 en cada ejecución |
| Corpus público pequeño | 4 audios FLEURS es_419; 60 palabras | Los mismos 4 audios |
| WER público ponderado por palabras | **3,333 %**: 2 errores | **1,667 %**: 1 error |
| Inferencia pública total | 6.472,604 ms | 2.055,640 ms |
| Inferencia pública mediana por archivo | 1.633,686 ms | 516,349 ms |

**Conclusión de esta comparación:** Vosk fue aproximadamente **2,23 veces más lento** en la mediana del caso privado, y tuvo más errores. No cumple la exigencia «misma velocidad o superior», ni la de conservar calidad sobre estas muestras. Se conserva como alternativa experimental con menor tamaño y carga más breve observada, no como sustituto aceptado del principal.

Vosk tardó 22,167–25,717 ms en el flush del caso privado, después de realizar 16,4–19,1 s de decode durante la alimentación acelerada de PCM. Esto no demuestra 25 ms de transcripción total ni latencia después de Detener con micrófono real. Preparación de archivos observada: 299,360 ms Vosk y 2.177,135 ms Sherpa, sin afirmar estado de caché frío uniforme.

### Evaluación de precisión y sus límites

WER usa distancia de edición por palabras en orden; ignora mayúsculas, puntuación y diacríticos. No convierte cifras a palabras, no introduce equivalencias de tecnicismos y no corrige la hipótesis. Las cifras, acrónimos o nombres pueden producir diferencias de normalización que deben analizarse por separado en una referencia exacta.

El caso privado tiene **referencia aproximada**, por lo que su WER es orientativo. No es un corpus etiquetado/alineado, no permite certificar precisión poblacional y su audio/transcripción no se incluyen aquí ni en logs/Git. Las cuatro frases públicas son voz humana leída y solo 60 palabras; no prueban español espontáneo peruano, vocabulario técnico nuevo, micrófono host ni Samsung físico. La discrepancia pública está concentrada en la muestra con un nombre propio; no demuestra cobertura de YEZVI/Kotlin/Compose/nombres ficticios.

Vosk usa diccionario fonético: su gramática contextual no equivale a hotwords BPE ni añade automáticamente palabras fuera de vocabulario. No se aplicó gramática restrictiva para mejorar artificialmente el A/B. La evaluación de tecnicismos necesita positivos acústicos y referencias exactas, además de controles negativos.

## 5. Empaquetado y gates pendientes

Existe un snapshot de auditoría [release-audit.json](../INVESTIGACION/F3.06-vosk/release-audit.json) de **82.040.275 B**, aproximadamente 78,24 MiB, anterior a las últimas actualizaciones de assets/avisos. No se presenta su hash como identidad del release final. Hay que regenerar/cotejar el paquete tras cada cambio y antes de distribuir, incluidas variantes posteriores con ASR-only.

[native-audit.json](../INVESTIGACION/F3.06-vosk/native-audit.json) y [app-native-audit.json](../INVESTIGACION/F3.06-vosk/app-native-audit.json) registran Vosk/JNA y la biblioteca nativa AndroidX preexistente por separado. MinSdk declarado de Vosk 21 permite satisfacer el requisito declarativo de YEZVI 24; no sustituye ejecución real en API 24/ARM64.

**Hallazgo técnico:** Vosk ARM64 y x86_64 tienen PT_LOAD 16 KB, pero finales GNU_RELRO no alineados a 16 KB (restos 12.288 y 8.192 respectivamente); JNA 64 bits tiene resto 0. El AVD probado usa páginas 4 KB. `zipalign` o PT_LOAD correcto no cierran el riesgo de carga/SIGSEGV en dispositivos de páginas 16 KB; hace falta reconstruir o conseguir binario corregido y ejecutarlo en ese entorno. No se atribuye este hallazgo al cierre histórico de otro runtime.

Gates abiertos: procedencia fuente/toolchain exacta del prebuilt; inventario final APK/AAB con todas las dependencias/avisos; exclusión de Sherpa en release; RELRO/ejecución 16 KB; ARM64/S24 Ultra/API 24 reales; prueba con micrófono; RAM/CPU/batería y límites térmicos; aceptación de calidad/latencia. No se anuncian cifras de RAM o consumo que no se midieron.

## 6. Diagnóstico adicional preparado, aún no ejecutado

`VoskPerformanceDiagnosticTest` prepara una comparación de cuatro perfiles sobre copia temporal del modelo privado, preservando el original verificado:

1. Configuración original (`beam=11`, `max-active=4000`, `lattice-beam=4`) con consulta de parcial cada 100 ms de audio.
2. Configuración original sin consultas de parciales.
3. `beam=10`, `max-active=3000`, `lattice-beam=3`, parciales cada 100 ms.
4. `beam=8`, `max-active=2000`, `lattice-beam=2`, parciales cada 100 ms.

Su propósito es distinguir coste nativo de decode y polling/JSON, y medir el compromiso velocidad/errores con menos búsqueda. **Todavía no tiene resultados.** No se aplica ninguna configuración reducida a producción ni se declara mejora. Un perfil más rápido requiere volver a medir WER y falsas inserciones sobre el mismo PCM antes de aceptarlo; bajar beam no garantiza conservar calidad.

## 7. Handoff y rollback

Mantener Vosk accesible como experimento explícito y Sherpa como principal del diagnóstico mientras se construye/valida el runtime **ASR-only autorizado** con NDK r28c y mismas redes FastConformer/Silero. Ese camino puede conservar el comportamiento conocido sin TTS/eSpeak, pero debe demostrar exclusión por fuente/mapa de enlace/binarios y medir rendimiento; una bandera CMake no certifica licencias.

Revisar [plan de auditoría](F3.06-plan-auditoria-distribucion.md) y [ejecución ASR-only](F3.06-runtime-asr-only.md). La autorización de descargar NDK y reconstruir no autoriza publicar los binarios. Preservar baseline y manifests para comparación. Si se retira Vosk, eliminar su dependency/assets/engine de la variante correspondiente y comprobar el paquete final; no modificar Room, no borrar recuerdos ni activar cloud como fallback.

Antes de cerrar F3.06 sigue siendo indispensable que el usuario hable realmente al micrófono con conectividad desactivada y obtener transcripción/latencias verificables. No se inicia F3.07 por este informe.
