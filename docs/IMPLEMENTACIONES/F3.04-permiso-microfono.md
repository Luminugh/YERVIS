# F3.04 — Permiso contextual de micrófono

**Fecha:** 2026-10-12  
**Alcance:** declaración y flujo runtime de `RECORD_AUDIO` desde Capturar. No se agregó grabación, STT, permiso de red ni guardado de voz.

## Comportamiento

- `AndroidManifest.xml` declara únicamente `android.permission.RECORD_AUDIO`.
- Capturar explica que el permiso prepara la función futura y que concederlo no graba ni transcribe. Solo el botón **Permitir micrófono** llama a `ActivityResultContracts.RequestPermission`; no se solicita al iniciar la app ni al abrir Capturar.
- Una denegación conserva disponible el borrador textual. Si Android sigue ofreciendo rationale, la acción permite reintentar. Después de una solicitud denegada sin rationale disponible, se muestra **Abrir ajustes** como acción opcional del usuario para abrir los detalles de YEZVI.
- La pantalla vuelve a consultar `checkSelfPermission` en `ON_RESUME`. Guarda únicamente dos indicadores locales de permiso (`solicitado` y `concedido alguna vez`) para identificar una revocación aunque el sistema termine el proceso al cambiar el permiso. No guarda audio, transcripción ni notas en esas preferencias.
- El estado concedido dice explícitamente que esta versión no graba ni transcribe. No se inicia ningún motor y F3.03 permanece desacoplada.

La API de solicitud sigue la guía oficial Android [Request runtime permissions](https://developer.android.com/guide/topics/permissions/requesting): verificar el estado, explicar el uso contextual, lanzar la petición tras la acción y respetar la denegación. El acceso a los detalles usa `Settings.ACTION_APPLICATION_DETAILS_SETTINGS` con el URI del paquete; el usuario decide si cambia el permiso.

- `assembleDebug` — `BUILD SUCCESSFUL`.
- `testDebugUnitTest` — **35 pruebas, 0 fallos**; incluye estados no solicitado/concedido/denegado/revocado y decisión del acceso a Ajustes.
- `connectedDebugAndroidTest` — **23/23, 0 fallos**, AVD Pixel 8 API 35. `CaptureDraftFlowTest` confirma que el estado de voz se muestra y el flujo de texto/revisión/descarte continúa.
- Validación manual AVD Pixel 8 API 35: no apareció el prompt al abrir Capturar; apareció después de pulsar la acción; denegar mostró el estado denegado y dejó el editor disponible; reintentar y conceder mostró el mensaje honesto; al revocar con `pm revoke`, Android reinició el proceso y YEZVI mostró “revocado” al regresar a Capturar; la acción **Abrir ajustes** abrió los detalles de la app y Atrás devolvió a ese estado. La conectividad no fue necesaria ni se cambió.
- No se capturó audio. El AVD valida el flujo de permiso del sistema, no el hardware de micrófono ni STT real. Samsung físico y API 24 siguen sin verificar.
- Al cierre, el APK debug quedó instalado y abierto en Capturar con el permiso sin conceder; no hay nota sintética creada por F3.04.
