# F2.08 — Timeline persistente

## Resultado

Memoria consume `MemoryRepository.observeAll()` y presenta únicamente entradas persistidas. La pantalla distingue carga, vacío, contenido y error recuperable; ya no usa fixtures ni muestra el aviso demo. Cada tarjeta navega con el ID real. Detalle consulta ese ID al repositorio y presenta el texto original, origen, fecha/hora en la zona registrada, zona horaria y estado de presentación.

## Implementación

- `YezviApp` reutiliza `YezviDatabaseFactory` y `RoomMemoryRepository`; Capturar y Memoria reciben la misma fuente Room en producción. Se mantiene la inyección para pruebas aisladas.
- `MemoryViewModel` expone un `StateFlow` respaldado por el Flow del repositorio, observa mientras la pantalla está activa (`WhileSubscribed(5 s)`), pasa cancelaciones y ofrece reintento ante errores.
- La agrupación de Memoria deriva el día local de cada entrada con su `timezoneId`. Dentro de cada grupo se ordena por `capturedAtEpochMillis DESC, id DESC`; los grupos se ordenan por la entrada más reciente.
- `EntryDetailViewModel` resuelve el registro por ID y diferencia carga, encontrado, inexistente y error con reintento. No se cambió esquema, DAO, navegación ni el diseño base de F1.05.
- El texto de Hoy ahora aclara que esa pantalla sigue mostrando ejemplos; Memoria y Detalle no mezclan demos con persistidos.

No hubo fallo de aserción de F2.08.
- Se ejecutó aisladamente `MemoryPersistenceTest.emptyTimelineUpdatesFromCaptureAndSurvivesActivityRecreation`: `BUILD SUCCESSFUL`, 1/1. El test borra únicamente su propio archivo temporal.
